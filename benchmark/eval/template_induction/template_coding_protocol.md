# Template Induction Experiment — Coding Protocol (FROZEN)

- **Frozen date**: 2026-07-16
- **Status**: FROZEN before any annotator saw the locked-test cases. No rule below may
  change after this date; any deviation must be logged in `report/experiment_report.md`
  under "Protocol deviations".
- **Claim under test**: under fixed semantic-relation extraction and merge/split rules,
  silent errors converge to a small, non-redundant catalog of constraint templates that
  covers most unseen cases. We test *reproducible / saturated / non-redundant /
  generalizable / deployable* — NOT that any particular catalog size is globally optimal.

## 0. Roles and blinding

| Role | Duty | Sees |
|---|---|---|
| Extractor (E1, E2) | Fill standardized fields per case | Whitelisted case fields only |
| Curator | Apply merge/split/admission rules; owns the catalog | Extractions + codebook |
| Rater A, Rater B | Independent locked-test verdicts | Whitelisted fields + frozen catalog |
| Adjudicator | Resolve A/B disagreements | Both raters' verdicts + case + catalog |

Every role is executed by an independent LLM annotator session with a fresh context.
Blinding is enforced by construction: annotator inputs are generated by
`make_inputs.py`, which whitelists fields; the paper's existing P1–P16 catalog,
`pattern_expansion/` outputs, and any prior template assignment are never included.

**Visible (whitelisted) fields**: `bug_id, framework, repo, title, description,
root_cause, category (13-class taxonomy), parallel_dimension, severity,
trigger_conditions, issue_url`.

**Hidden fields** (encode prior template analysis; annotators must derive these
independently): `invariant, invariant_type, detection_method, detection_signal,
required_trace_fields, check_stage`, and all `pattern_id` / P1–P16 labels.

Evidence source note: `title/description/root_cause` are curated summaries of the
upstream issue and fix; annotators use them as `evidence_from_issue`/
`evidence_from_fix`. Live issue fetching is not part of this run (logged as a
scoping decision, not a deviation).

## 1. Standardized extraction schema

Each case must be coded into:

```
case_id                  # bug_id
semantic_objects         # framework-agnostic objects, normalized vocabulary below
expected_relation        # one relation operator from the open list below
observable_signal        # what runtime-measurable signal would witness a violation
topology_scope           # e.g. TP>1, DP>1, EP>1, PP>1, any, single-rank
validity_precondition    # when/for which modules the relation must hold
training_phase           # init | forward | backward | optimizer_step | checkpoint_save |
                         # checkpoint_load | data_loading | eval | any
evidence_from_issue      # quote/paraphrase from title/description
evidence_from_fix        # quote/paraphrase from root_cause (fix-derived)
confidence               # high | medium | low
```

Normalization rules for `semantic_objects`: strip framework-specific class names to
roles (e.g. `ZeroOptimizer partition` -> `sharded optimizer state`;
`router.expert_bias` -> `replicated parameter`). Relation operators are open-coded but
must be one predicate over measurable quantities (equality, proportionality,
conservation/sum-to-one, monotonicity, invariance-across-config, count/frequency match,
restoration-after-reload, boundedness, ordering, exclusivity, ...). One case may yield
one primary relation; secondary relations may be listed but only the primary is used
for template induction.

## 2. Merge rule (two cases -> same template)

Merge iff ALL hold:
1. Same `expected_relation` operator.
2. `semantic_objects` identical after framework-agnostic renaming.
3. All remaining differences expressible purely as topology / phase / precondition guards.
4. The merged template still admits ONE executable schema predicate.

## 3. Split rule

Split iff ANY holds:
1. Different relation operator (e.g. equality vs monotonicity).
2. Compared objects play different semantic roles.
3. Merge would require unrelated `OR` branches.
4. No single observable signal covers the merged set.
5. Merged predicate would flag legal executions.

## 4. New-template admission rule

A recurring template requires:
1. ≥2 mutually independent supporting cases (different incidents; same issue/fix
   duplicates count once).
2. An explicit, writable schema predicate.
3. Not expressible as an existing template plus guards.

Relations seen once are held as `singleton` and are NOT promoted.

## 5. Dataset split (frozen before annotation)

| Set | N | Use |
|---|---:|---|
| Seed | 128 | Initial catalog induction |
| Development stream | 186 | Batch-wise catalog extension; stopping rule |
| Locked test | 78 | Final validation after catalog freeze |

Constraints: stratified by 4 frameworks × 13 taxonomy classes; same-issue /
same-fix / duplicate-root-cause cases share one leakage group and one split; all 18
Real-SE cases (mapped to pool bug_ids, LC1 -> O-003) go to locked test, topped up to
78 by stratified sampling; seed reconstructs the original 128-pool membership
(`source_pool ∈ {128_only, both}`) minus any case pulled into locked test, refilled
from the development pool by stratified sampling. RNG seed = 20260716. No temporal
split: 0/392 cases have `fix_date`.

The locked test set must not be used to add, merge, or split templates at any point.

## 6. Development procedure

Shuffle the 186 development cases once (RNG seed 20260716), process in batches of 25
(last batch 11). Per batch record: #matched to existing templates, #new singletons,
#new recurring templates admitted, #merge/split edits to existing templates,
cumulative coverage, cumulative template count.

**Stopping rule (pre-registered)**: stop when, simultaneously,
(a) 3 consecutive batches admit no new recurring template;
(b) ≥95% of each of those batches maps to existing templates;
(c) new singleton share <5% in each;
(d) no core schema relation of an existing template was modified.

When triggered: record the simulated stopping point, freeze that catalog snapshot,
KEEP processing remaining batches without modifying the frozen snapshot, and compute
post-stop regret (recurring relations appearing after stop; extra coverage foregone;
whether any frozen template would have needed modification).

Order-robustness: after final adjudicated coding, simulate ≥200 random reorderings of
the development stream and report the median and 5–95% band of both saturation curves
(cases -> #templates; cases -> coverage).

## 7. Locked-test procedure

Catalog is frozen (hash recorded) before any rater sees a test case. Per case, each
rater independently outputs exactly one verdict:

```
MATCH(template_id) | SINGLETON_NEW_RELATION | UNOBSERVABLE | REFERENCE_DEPENDENT |
NON_GROUNDABLE | INSUFFICIENT_EVIDENCE
```

plus, for MATCH: whether topology and precondition guards are instantiable
(`groundable: yes/no + reason`). Raters A and B run in independent sessions with
different prompt framings; neither sees the other's output. The adjudicator resolves
disagreements and never contributed initial verdicts.

Metrics: schema coverage C_schema = matched / 78; joint groundability C_joint =
fully groundable / 78; novelty rate N = genuinely-new-relation / 78; per-framework
breakdowns of each; compression stats (templates, support per template, singleton count).

Inter-rater reliability: raw agreement and Cohen's κ on (i) match-vs-uncovered,
(ii) template assignment among matched, (iii) 6-way verdict; plus E1/E2 agreement on
`expected_relation` over a 25% random subset of seed+development extractions
(κ reported separately from the paper's 13-class taxonomy κ=0.566, which does not
transfer to template induction).

## 8. Redundancy audit

For the final catalog of K templates, audit all K(K-1)/2 pairs: same normalized schema
relation? differences guard-expressible? merge introduces unrelated disjunction? merge
degrades executability or flags legal runs? Claim at most: "irredundant under our
predefined merge criterion" — never global minimality.

## 9. Uncovered-case analysis

Every uncovered locked-test case must land in exactly one of:
`U1 Unobservable` / `U2 Reference-dependent` / `U3 Statistical` /
`U4 Non-groundable` / `U5 Singleton` / `U6 Insufficient evidence`,
with a one-line justification, reported as a table (not a bare percentage).

## 10. Pre-registered success criteria (fixed before results)

- Held-out schema coverage ≥ ~80%;
- C_schema − C_joint gap explainable case-by-case;
- Post-stop coverage regret ≤ 2 pp;
- ≤1–2 new recurring relations in locked test;
- Template-assignment agreement reaches substantial agreement (κ ≥ 0.61);
- No pair survives the merge audit as obviously mergeable;
- Every major template has ≥2 independent supporting cases;
- Most uncovered cases land in U1–U4 (systematic boundary), not U6 (coding failure).

Negative results are reported as-is with their diagnostic interpretation
(unsaturated catalog / ambiguous rules / guard bottleneck / weak cross-framework
abstraction).
