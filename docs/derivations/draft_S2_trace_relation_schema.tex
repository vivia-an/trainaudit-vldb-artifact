\paragraph{Silent error as a guarded constraint violation.}
We model the runtime training state as the relations of Table~\ref{tab:trace-relations} and define a silent error as a violation of a guarded data-quality constraint over them that raises no explicit exception. A constraint is a tuple $C = (R, A, G_{\text{topo}}, G_{\text{phase}}, V)$: it reads attributes $A$ of relation $R$, applies a topology guard $G_{\text{topo}}$ and a phase guard $G_{\text{phase}}$, and flags rows violating the predicate $V$. This is exactly the three-predicate decomposition $p(s) = \pi_{\text{schema}} \wedge \pi_{\text{topo}} \wedge \pi_{\text{precond}}$ realized in SQL:
\begin{quote}\small\ttfamily
SELECT ... FROM R WHERE G\_topo AND G\_phase GROUP BY ... HAVING V;
\end{quote}
An empty result means the constraint holds (pass); a non-empty result is a \emph{violation table} that both flags and localizes the fault. Because every relation is a view over the single \texttt{coredump} table, adding a check requires no schema migration---only a new query and, where needed, an additional traced field (the schema-tier choice quantified in \S\ref{subsec:efficiency}).
