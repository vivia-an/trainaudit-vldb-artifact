## 逐个复现的工作流（模板化）

每个 bug 的复现步骤：

### Step 1: 确认 commit
- 打开 issue URL
- 找到对应的 fix PR/commit
- 手动确认 `git diff buggy fixed` 的内容和 issue 描述一致
- 如果 commit 错了，重新查找

### Step 2: 复制模板
```bash
BUG=M-xxx
mkdir -p exp/data/reproductions/$BUG
cp exp/sdctrace/benchmark/run_with_trace_template.py exp/data/reproductions/$BUG/run_with_trace.py
```

### Step 3: 写 run_pretrain.sh（每个 bug 独立）
关键：正确的触发参数。需要分析 issue + fix diff 判断：
- TP/PP/DP 各需要多少？
- 需要 MoE？distributed optimizer？overlap？
- 需要 FP16 还是 BF16？
- 支持 --mock-data 吗？不支持用假数据
- buggy/fixed 的参数区别（Type A vs Type B）

### Step 4: 写 reproduce.sh
从 M-005 的 reproduce.sh 复制修改 commit 和参数即可。

### Step 5: 跑
```bash
cd exp/data/reproductions/$BUG
bash reproduce.sh
```

### Step 6: 分析结果
- 如果 distinguishable=True → 成功
- 如果 trace 有数据但 diffs=0 → bug 没触发，调参数
- 如果 trace 无数据 → 训练失败，看 log 修
