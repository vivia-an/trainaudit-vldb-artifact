### C3：LLM 提取 L2/L3 知识（核心实验，未开始）

这是论文最关键的实验，证明 LLM 的价值。

**实验 3a：LLM 提取 TP parameter classification（L2）**

步骤：
1. 人工分析 Megatron 源码，标注每个参数在 TP 下是"应该相同"还是"应该不同（shard）"→ ground truth
2. 让 LLM 分析相同的源码，生成相同的标注
3. 对比 precision / recall / F1

预期结果：LLM 能正确分类 80%+ 的参数（高 recall，部分 precision loss）

**实验 3b：LLM 提取 bug precondition（L3）**

步骤：
1. 从 128 个 bug 中挑 20 个有明确 fix commit 的
2. 给 LLM：issue 描述 + fix commit diff
3. 让 LLM 输出：完整的 precondition（什么配置/环境下 bug 触发）
4. 对比：LLM 输出的 precondition vs 我们真实复现中发现的 precondition

预期结果：LLM 能提取 60-70% 的显式 precondition，但会遗漏隐式的（如 CPU/GPU init）

**实验 3c：LLM 生成 structured invariant spec**

步骤：
1. 给 LLM 源码 + 我们的 JSON schema 格式
2. 让 LLM 生成 `{check, field, across, at, when}` 格式的 invariant
3. 编译成 SQL，在真实 trace 上运行
4. 统计：生成的 invariant 中有多少能正确检测 bug、有多少 FP

**工作量**：3-5 天
**产出**：Table 3（LLM vs Human parameter classification）+ Table 4（precondition extraction recall）+ Table 5（invariant 质量）

### C4：端到端真实复现（需要 10-15 个成功案例）

不需要全部 128 个。挑 **15 个最有代表性的**，覆盖：
- 不同 category（gradient_sync、numerical、communication、sharding、checkpoint、control_flow）
- 不同 parallel dimension（DP、TP、PP、none）
- 不同 invariant type（cross_rank_equality、bounded_change、dtype_consistency）

**15 个候选（按复现难度排序）**：

**容易（无需特殊配置，DP only）**：
1. M-020：VPP 整除 bug → 检查 num_layers 是否等于配置值
2. M-010：MoE aux loss 翻倍 → 检查 loss 是否异常大
3. M-004：MTP loss 未归一化 → 检查 grad_norm 是否异常大

**中等（需要 TP 或特殊参数）**：
4. M-005：router weight TP 不同步 → 需要 GPU init 或改用更新版本
5. M-014：router topk-softmax 顺序 → 检查 routing 行为
6. M-012：expert_bias dtype 变化 → 检查 dtype 一致性
7. M-021：expert 参数不更新 → 检查 cksum 跨 step 不变

**较难（需要特定框架交互）**：
8. M-007：stale weights with overlap-param-gather → 需要 overlap 通信
9. M-015：LR override 不生效 → 需要 checkpoint resume
10. M-016：optimizer offload checkpoint loss 跳变 → 需要 CPU offload

**跨框架（DeepSpeed / OLMo）**：
11. D-xxx：ZeRO gradient accumulation bug
12. D-xxx：CPU offload gradient discard
13. O-xxx：FSDP gradient accumulation
14. O-xxx：checkpoint resume
15. O-xxx：loss computation

**复现策略：分三批**

| 批次 | Bug 数 | 方法 | 时间 |
|------|--------|------|------|
| 第一批 | 5 个 | 真实 Megatron + pretrain_wrapper | 3-5 天 |
| 第二批 | 5 个 | 真实 Megatron/DeepSpeed | 3-5 天 |
| 第三批 | 5 个 | 补齐跨框架多样性 | 3-5 天 |

**工作量**：10-15 天
