# 03 · 故事 B：问错了问题（The Wrong Question）

> **配合故事 A 使用，作为 Abstract / Introduction 的钩子句。**

## 故事的核心 motif

过去十年，LLM 训练的 observability 工具——loss curve、gradient norm、NaN/Inf check——都在回答**同一个问题**：

> *"这次训练**正常吗？**"*

这是一个**统计问题**，问的是聚合标量是否在历史经验区间里。

但 silent error 的本质从来不是"统计偏离"，而是"**算法语义被违反**"——你想要 accumulate 的时候它在 overwrite，你想要 all-reduce 的时候它没 reduce，你想要 reset 的时候它没 reset。这些违反在 loss 上**几乎不留痕迹**，因为它们破坏的是过程，不是结果。

要识别这种违反，正确的问题应该是：

> *"这次训练**忠于我们写下的算法吗？**"*

这是一个**语义问题**，问的是 distributed state 之间的关系是否符合算法 spec。

**这个问题过去无法被机械地问出来**——不是因为没数据，而是因为没人能把"算法 spec"翻译成可在 runtime 自动检查的形式。AI 第一次让这件事可行。

## 三个对照命题

| 维度 | 错的问题（现状） | 对的问题（TrainAudit） |
|---|---|---|
| **观察对象** | scalar aggregate（loss、grad norm） | distributed state（参数、optimizer state、计数器、并行组）|
| **判定方式** | 统计偏离阈值 | 语义关系是否成立 |
| **检测时机** | 偏离累积到肉眼可见 | 关系一旦违反即触发 |
| **可解释性** | "loss 跳了"——不知道为什么 | "DP rank 0 和 rank 1 的 final_layernorm.bias checksum 不一致"——直接定位 |

## Abstract 钩子句样板

### v1（推荐）
> For a decade, the observability of LLM training has answered the wrong question. We have asked *is the training healthy?*—a statistical question over scalar aggregates—when we should have been asking *is the training faithful to its intended algorithm?*—a semantic question over distributed state. The latter requires translating algorithmic intent into runtime-checkable form, an operation that has only become feasible at scale with the maturation of code-comprehending LLMs.

### v2（更克制）
> Silent errors in distributed LLM training are not detected late because the data hides them—they are detected late because the questions we ask of the data are wrong. Loss curves and gradient norms ask whether training is statistically healthy; what we need to ask is whether training is semantically faithful to its intended algorithm.

## 这个故事擅长解决什么问题

### 优势 1：给"为什么 loss / grad norm / NaN check 都不够"一个清楚的解释
现在的 §1 用了好几段话解释这一点，措辞东一句西一句。"问错了问题" 这个 frame 让它**一句话就 self-evident**。

### 优势 2：让 SQL verifier 的位置变得自然
如果问题是"distributed state 之间的关系是否成立"，那 SQL（关系代数）就是这个问题在工程上的**最自然语言**。verifier 用 SQL 不是技术选型，是 problem framing 的直接结果。

### 优势 3：让"intent-anchored invariant"这个概念词不需要解释
当读者已经接受了"我们要检查的是算法忠诚度"，"intent-anchored invariant" 就是这个 frame 下的自然命名——不需要额外推销。

## 这个故事单独不够用的原因

故事 B **回答的是 "为什么过去做不好"**，但不回答 **"为什么现在可以做"**。

如果只用 B，审稿人会问："这个对的问题为什么过去十年没人去问？"——答案必须回到故事 A 的 rule deficit 框架（因为提出问题需要把 spec 翻译成可执行规则，而规则供给被人类成本锁死了）。

所以建议用法是：

- **B 作为 Abstract 第一句和 Introduction 第一段的钩子**（让人立刻好奇）
- **A 作为 Introduction 第二段开始的展开**（解释为什么这个问题现在才能问）
- **两者在 §3 概览处合流**：TrainAudit 同时回答了"问什么对的问题"和"现在为什么能问"。

## 风险与反驳预案

### 风险 1：审稿人觉得"问错了问题"语气太大
**预案**：把"wrong question"在正式 paper 里换成"the question being asked is the answer to a different problem"——意思一样，但少了攻击性。Abstract 用强版本，正文用克制版本。

### 风险 2：被指责贬低 loss / grad norm 的价值
**预案**：在 §2 明确说明 loss / grad norm 仍然是 trainability 的有效信号，TrainAudit 不替代它们；它解决的是 loss 信号无能为力的那一类（semantic logic faults）。两类信号互补。

### 风险 3：审稿人问"算法忠诚度具体是什么意思？能严格定义吗？"
**预案**：给一个工作定义：

> **算法忠诚度（Algorithmic Faithfulness）.** 一次执行 $e$ 是 *忠于* 算法 spec $\mathcal{A}$ 的，当且仅当 $e$ 在每一步生成的 distributed state 都满足 $\mathcal{A}$ 隐含的所有 invariant 集合 $\mathcal{P}$。Silent error 检测即是判定 $e$ 是否忠于 $\mathcal{A}$。

这个定义和现有 §2.2 的形式化是兼容的，但更紧贴 frame B 的措辞。

## 一段总结

故事 B 是一把"开门用的钥匙"——它让读者在前 30 秒就理解为什么这篇论文重要，但单独支撑不了整篇。它和故事 A 配合：B 让人产生好奇（为什么我们一直在问错的问题），A 给出答案（因为问对的问题成本太高、AI 改变了这件事）。
